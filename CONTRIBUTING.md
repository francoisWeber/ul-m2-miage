# Contributing to Data Engineering Workshop

Thank you for your interest in contributing! This document provides guidelines for contributions.

## Types of Contributions

### 1. New Workshop Notebooks
- Add educational content for students
- Include clear explanations and exercises
- Follow the existing notebook structure
- Test thoroughly before submitting

### 2. Bug Fixes
- Fix configuration issues
- Improve error handling
- Update documentation

### 3. Performance Improvements
- Optimize Docker configurations
- Improve resource allocation
- Enhance query performance

### 4. Documentation
- Fix typos and clarify instructions
- Add troubleshooting guides
- Translate to other languages

## Getting Started

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature`
3. Make your changes
4. Test thoroughly
5. Submit a pull request

## Development Guidelines

### Code Style
- Use meaningful variable names
- Add comments for complex logic
- Follow Python PEP 8 for Python code
- Use shellcheck for bash scripts

### Testing
- Test all services start correctly
- Verify notebooks run without errors
- Check all connections work
- Test on fresh installation

### Documentation
- Update README.md if adding features
- Document configuration changes
- Add inline comments
- Update ARCHITECTURE.md for structural changes

## Submitting Changes

### Pull Request Process
1. Update documentation
2. Test your changes
3. Describe your changes clearly
4. Reference any related issues
5. Wait for review

### Commit Messages
Use clear, descriptive commit messages:
- `feat: add Kafka streaming notebook`
- `fix: correct MySQL connection timeout`
- `docs: update installation instructions`
- `perf: optimize Spark worker configuration`

## Questions or Problems?

Open an issue on GitHub or contact the maintainers.
